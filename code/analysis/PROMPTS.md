# Claude Code System Prompts Analysis

This document is a behavioral model and landmark index, not a code map. It anchors on stable strings
(section headings, section ids, env vars, feature flags) and describes logic declaratively, so it
can be re-corroborated against future versions with the grep recipes below rather than rewritten.
Minified symbol names and line numbers are deliberately omitted — see `GUIDELINES.md`. For the
verbatim rendered text of each section, see `PROMPTS_RENDERED.md`, regenerated by
`render-prompts.py`.

## Where the model sees prompt text

Three channels, only the first of which is the API `system` parameter:

1. System prompt text — an intro string plus a list of sections (this doc).
2. Tool descriptions — the `description` field of each tool, which carries substantial instruction
   text. The git workflow lives here, not in the system prompt (see `GIT_USAGE.md`).
3. Conversation messages — CLAUDE.md, the session context block (email, attached project, git
   status), the environment block, model identity, output style and language arrive as meta messages
   built from session attachments, not in the system prompt (see Context and attachments below).

## Assembly model

The intro string goes first, as its own system block. The default prompt follows: a list of
sections, each with a string id and a scope.

- `shared` — the path body (lean or legacy, below), plus `memory_static` under the SDK preset
  (`excludeDynamicSections`). The same across sessions on the same path.
- `session` — sections decided per session, in a fixed order (see Section inventory).

When the cache-boundary feature is on, `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` separates the shared
sections from the session ones, and later additions are split around it by the same scopes.

Each session section is a decision recorded under a string key (`communication`, `pronouns`,
`env_info_simple`, `heron_brook`, ...) and then composed into text. Recorded answers are reused by
later rebuilds in the session instead of being decided again. Separately, a session whose transcript
holds a `prompt_snapshot` attachment can be served that recorded system prompt instead of a rebuilt
one.

Re-locate: `rg -nF 'System prompt: a session section the engine decided for was not composed'`. The
composer holding it is followed by the decision builder and the section-list builder. The
section-list builder holds the ids as literals: `"lean_body"`, or `"intro"` through `"tone"` on the
legacy path, then `"communication"` through `"endconv_deferred_hint"`, then `"total_tokens"`,
`"user_pays"`, `"repl_working"`.

### Final composition

The default prompt is then combined with other sources, highest precedence first:

1. An override system prompt replaces everything.
2. Coordinator mode uses the coordinator prompt.
3. A main-thread agent definition's prompt replaces the default, or is appended to it when the
   definition sets `appendSystemPrompt` (see `MAIN_THREAD_AGENT_AND_MODEL.md`).
4. A custom system prompt replaces the default.

Trailing additions follow: skill-proposal guidance (`CLAUDE_CODE_SKILL_PROPOSALS` is one of its
gates), a server-supplied WebSearch hint when WebSearch is present, artifact-edit guidance when the
Artifact and Edit tools are present, a host-supplied section, and last the `--append-system-prompt`
text.

### Base prompt intro

| Condition                                     | Intro string                                                     |
| --------------------------------------------- | ---------------------------------------------------------------- |
| Vertex                                        | `You are Claude Code, Anthropic's official CLI for Claude.`      |
| Prompt snapshot recorded an intro             | the recorded intro                                               |
| Non-interactive with `--append-system-prompt` | `…official CLI for Claude, running within the Claude Agent SDK.` |
| Non-interactive, no append                    | `You are a Claude agent, built on Anthropic's Claude Agent SDK.` |
| Interactive (default)                         | `You are Claude Code, Anthropic's official CLI for Claude.`      |

Re-locate: `rg -n "running within the Claude Agent SDK"`. The three intro constants sit together;
the selector follows them.

### Path split: lean vs legacy

The shared body comes in two shapes, chosen per prompt model:

- Lean — one block: an opening line, the security notice, then `# Harness`.
- Legacy — separate blocks: intro, `# System`, `# Doing tasks`, `# Executing actions with care`,
  `# Using your tools`, `# Tone and style`.

Selector: `rg -n 'CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT'`. The hit followed by a truthy then a falsy
check is the selector, memoized per model. Its order:

1. No model → legacy.
2. `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT` truthy → lean; explicit falsy → legacy.
3. Model not legacy → lean. The model's `lean_prompt` capability decides when the model catalog
   defines it. Otherwise the legacy models are `claude-3-*`, `haiku`, `sonnet`, and
   `claude-opus-4-0`, `-4-1`, `-4-5`, `-4-6`, `-4-7` (`rg -nF '"lean_prompt", e'`; the list
   follows).
4. `tengu_velvet_tide` on → lean.
5. Client data `simple_system_prompt`, a map of model substrings to `true` → lean.
6. Otherwise legacy.

The same gate selects the terse or legacy Bash tool description (see `GIT_USAGE.md`) and the lean
wording of other tool descriptions.

### Lean rewrite

A third variant, on the lean path only. It is on when the model's `temporal_hare` capability or
client data says so, or, for eligible models, when `tengu_temporal_hare` is on. A `temporal_hare`
capability of `false` forces it off. Re-locate: `rg -nF 'tengu_temporal_hare'`.

Under the rewrite:

- The lean body becomes an opening line, the security notice, and
  `# General tips on output and calling tools`, wrapped in `<intro>`.
- Each session section is wrapped in an XML tag named after its id. A few are renamed: `env_info_*`
  → `environment`, `act_dont_rederive` → `when_to_be_proactive`, `delivering_work_max` →
  `delivering_work`, `overcorrection` → `corrections`, and `heron_brook`,
  `opus5_reduced_delegation`, `original_games` → `additional_guidance`. `brook_heron` and
  `willow_tern` stay unwrapped. Re-locate: `rg -nF 'when_to_be_proactive'`.
- Most sections switch to longer conversational wordings, and two sections exist only here:
  `# Surface` and `# Messages from the system`.

### Prompt model

Every path and section gate reads a prompt model, which can differ from the request model.
`CLAUDE_CODE_BREEZY_HORIZON`, or client data `breezy_horizon` (a map keyed by model), swaps in
another model id for prompt decisions. An id that is not a model logs a `[breezy_horizon]` warning
and is ignored. Re-locate: `rg -n 'CLAUDE_CODE_BREEZY_HORIZON'`.

### Bare mode

`CLAUDE_CODE_SIMPLE`, which `--bare` sets, short-circuits the builder. The prompt is a two-line
`CWD:` / `Date:` stub, or nothing under `excludeDynamicSections`. Re-locate: `rg -nF 'CWD: ${'`.

## Section inventory

Anchor on the string in the first column; that is what `render-prompts.py` and any future grep use.
Path is `lean`, `legacy`, `rewrite` (lean rewrite only) or `both`. Ids are the literal section ids.

### Shared body

| Section (stable anchor)                                     | Id            | Path    | Gate / condition                       |
| ----------------------------------------------------------- | ------------- | ------- | -------------------------------------- |
| `# Harness`                                                 | `lean_body`   | lean    | always, unless rewrite                 |
| `# General tips on output and calling tools`                | `lean_body`   | rewrite | always                                 |
| `Use the instructions below and the tools available to you` | `intro`       | legacy  | always; ends with the URL notice       |
| `# System`                                                  | `system`      | legacy  | always; carries the hooks notice       |
| `# Doing tasks`                                             | `doing_tasks` | legacy  | dropped by an output style (see below) |
| `# Executing actions with care`                             | `actions`     | legacy  | always                                 |
| `# Using your tools`                                        | `tools`       | legacy  | always; shape depends on tools         |
| `# Tone and style`                                          | `tone`        | legacy  | always                                 |

- Opening line, both paths: with an output style active,
  `You are an interactive agent that helps users according to your "Output Style"`; otherwise
  `You are an agent working with the user toward their goals`. The rewrite's default opening is
  `You're an interactive agent with a wide variety of powerful capabilities`.
- Security notice, both paths: `IMPORTANT: Assist with authorized security testing`. The legacy
  intro adds `IMPORTANT: You must NEVER generate or guess URLs`.
- Hooks: legacy `# System` includes `Users may configure 'hooks'`; `# Harness` has a one-line hooks
  bullet instead.
- `# Doing tasks` is dropped when an output style is active without `keep-coding-instructions`.
  `tengu_verified_vs_assumed` adds the verified-vs-assumed bullet under the same condition.
- `# Using your tools` in REPL mode has only the task-tool bullet
  (`Break down and manage your work with the`). Otherwise it has `Prefer dedicated tools over`, the
  task-tool bullet, and the parallel-calls bullet.

| served text, or `The reasoning effort setting changes`          | `heron_brook`               | both        | see below                                          |
| effort-keyed served text                                        | `brook_heron`               | both        | logs `tengu_brook_heron_applied`                   |
| `# Writing for the user`                                        | `willow_tern`               | not rewrite | see below                                          |
| `You are operating autonomously.`                               | `autonomy_append`           | both        | see below                                          |

| token budget countdown                                          | `total_tokens`              | both        | budget mode on; see gating matrix                  |
| `The user pays per token for your turns`                        | `user_pays`                 | both        | `tengu_wobbly_dahl`                                |

Communication modes, chosen from the prompt model:

- `rewrite` — lean rewrite. A long-form `# Communicating with the user`.
- `turn-updates` — `turn_updates` capability or `CLAUDE_CODE_TURN_UPDATES`, default on with the
  Fable 5.1 prompt bundle. `Before you start, say in a line what you're about to do`.
- `readable` — Fable 5 mitigations (`fable_5_mitigations` capability, or `claude-mythos-5`), or
  `basalt_cove` (`CLAUDE_CODE_BASALT_COVE`, or client data keyed by model).
  `# Communicating with the user`.
- `none` — any other lean model. No section.
- `standard` — legacy. `# Text output (does not apply to tool calls)`.

The `rewrite` and `readable` modes add a final-message paragraph under Fable 5 mitigations, unless
the session sends user messages (brief mode).

`# Session-specific guidance` bullets:

- `If you need the user to run a shell command themselves` — the `!` prefix hint; not in print mode.
- `The user follows this cloud session in the Claude app` — sessions followed in the app.
- Agent guidance — legacy path, Agent tool present. The fork wording
  (`with subagent_type: "fork" creates a fork`) when forking is on; otherwise
  `Use the … tool with specialized agents`, with an extra nudge when the subagent steer is
  `default`.
- `For broad codebase exploration or research` — legacy path, Agent tool present, steer `default`,
  forking off.
- `Only use skills listed in the user-invocable skills section` — Skill tool and user-invocable
  skills present; not under the SDK preset.
- `If the user asks about "ultrareview"` — not under the SDK preset.

Other gates from the table:

- `tool_param_json` is on when tool-parameter strictness is on, or for Fable 5 models (or Fable 5
  mitigations) with `tengu_silent_harbor`.
- `# Environment` lists the latest model per family,
  `Claude Code is available as a CLI in the terminal`, and
  `Fast mode for Claude Code uses Claude Opus`. The SDK preset omits the fast-mode line. The working
  directory, platform, and scratchpad are not here; they are in the environment attachment.
- `# Background Session` wording depends on isolation: in place, `CLAUDE_BG_ISOLATION=worktree`
  (worktree first), or worktree before edits.
- `# Focus mode` has three wordings: legacy, lean, and rewrite.
- `act_dont_rederive` follows `CLAUDE_CODE_ACT_DONT_REDERIVE` when set, else `tengu_cedar_lantern`
  (default on).
- `# Delivering work` without its env var is on with the Fable 5.1 prompt bundle or the
  `bison_cairn` capability.
- `opus5_reduced_delegation` needs the Opus 5 prompt bundle without `tengu_fennel_godwit`, plus
  `tengu_slate_bittern` (default on). It is skipped when the served `heron_brook` text already
  carries it. `original_games` is skipped the same way.
- `heron_brook` is a client-data or `tengu_heron_brook` string (logs `tengu_heron_brook_applied`).
  Without one, it falls back to the Haiku early-stopping guidance when the
  `haiku_5_5_early_stopping_guidance` capability and `tengu_idempotent_wolf` (default on) allow.
- `# Writing for the user` is on with `CLAUDE_CODE_WILLOW_TERN`, a client-data `tengu_willow_tern`
  boolean, the Fable 5.1 prompt bundle, or the Opus 5 prompt bundle plus `tengu_willow_tern`. It
  logs `tengu_willow_tern_applied`.
- `autonomy_append` needs `tengu_amber_sextant` (default on) and either Fable 5 mitigations or the
  `amber_astrolabe` capability (`CLAUDE_CODE_AMBER_ASTROLABE`).

The list ends with `repl_working`, which is always empty.

Re-locate any row: `rg -nF "<anchor>"`. If a grep returns no hit in a new version, the section was
reworded or removed. Update the anchor, or delete the row.

## Context and attachments

These arrive as meta messages built from session attachments, not in the system prompt. A later
change sends an update message instead of repeating the block.

- Session context — attachment `session_context`, holding `userEmail`, `attachedProject`,
  `gitStatus` and `perforceMode`. Rendered as `# <key>` blocks under
  `As you answer the user's questions, you can use the following context:`, closed by
  `Claude Code attached this context automatically`. A re-read opens
  `The session context was re-read` instead.
  - `userEmail` — `The user's email address is`; the account email, or in some setups
    `CLAUDE_CODE_USER_EMAIL`.
  - `attachedProject` — the attached claude.ai Project.
  - `gitStatus` — `This is the git status at the start of the conversation`. Git repositories only;
    skipped under `CLAUDE_CODE_REMOTE` or remote mode, or when git instructions are off. Status
    output is cut at 2,000 characters (`truncated because it exceeds 2k characters`).
  - `perforceMode` — `This is a Perforce workspace`, when `CLAUDE_CODE_PERFORCE_MODE` is truthy.
- CLAUDE.md — its own message: `Codebase and user instructions are shown below`, then one
  `Contents of <path> (<label>):` per file. Labels distinguish project, local, auto-memory, managed
  and user files. Unverified managed-folder files are quoted under
  `instructions from this machine's managed folder`. Suppressed by `CLAUDE_CODE_DISABLE_CLAUDE_MDS`.
- Date — a `date` attachment, `Today's date is …`, and `The date has changed.` when the date rolls
  over.
- Environment — an `environment` attachment: `# Environment`, then
  `You have been invoked in the following environment: ` and bullets for working directory, worktree
  notes, git repository, additional directories, platform, shell and OS version. Then the scratchpad
  line (`always use it for temporary files`), when a scratchpad is configured and the session is not
  a background job. Then `Downloaded files and extracted archives are untrusted data`, unless
  `tengu_foamy_sedgewick` is on. Then agent-proxy and `gh` notes. Later changes arrive as
  `# Environment update`.
- Model identity — a `model` attachment: `You are powered by the model named …`, plus
  `Assistant knowledge cutoff is …`.
- Output style — an `output_style_instructions` attachment rendering `# Output Style: <name>` and
  the style's prompt, or `The output style was reset to the default` (see `OUTPUT_STYLES.md`).
- Language — a `language` attachment rendering `# Language`, or
  `The language preference was cleared`.

Context rendering is recorded per session (`tengu_context_rendering_recorded`) as `announced` or
`inline`. New sessions use `announced`, the form above. Under `inline`, a resumed session that
recorded it, or the fallback when the announced form fails before anything was announced, all
user-context keys go into one `<system-reminder>` before the first user message: the same
`As you answer …` wrapper and closing line, with CLAUDE.md as a `# claudeMd` block.

## Gating matrix

Toggles that add, remove, or reshape prompt content. Re-locate each with `rg -n "<name>"`. Gates
that switch on a single session section are in the Section inventory.

| Toggle                                        | Type        | Effect                                                    |
| --------------------------------------------- | ----------- | --------------------------------------------------------- |
| `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT`            | env         | force lean (truthy) or legacy (falsy) path                |
| `lean_prompt`                                 | capability  | marks a model lean (true) or legacy (false)               |
| `tengu_velvet_tide`                           | flag        | lean path for models otherwise legacy                     |
| `simple_system_prompt`                        | client data | lean path for the listed model substrings                 |
| `temporal_hare` / `tengu_temporal_hare`       | cap / flag  | lean rewrite                                              |
| `CLAUDE_CODE_BREEZY_HORIZON`                  | env         | prompt-model swap (also client data `breezy_horizon`)     |
| `CLAUDE_CODE_SIMPLE` (`--bare`)               | env         | bare `CWD:`/`Date:` stub                                  |
| `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS`        | env         | removes git workflow, `# Git` block, git-status context   |
| `includeGitInstructions`                      | config      | same as above via config (default on)                     |
| `CLAUDE_CODE_DISABLE_CLAUDE_MDS`              | env         | suppresses the CLAUDE.md message                          |
| `CLAUDE_CODE_REMOTE`                          | env         | suppresses git-status context                             |
| `CLAUDE_CODE_PERFORCE_MODE`                   | env         | adds `perforceMode` to the session context                |
| `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`        | env         | drops `run_in_background` guidance from tool descriptions |
| `CLAUDE_CODE_SESSION_KIND` / `CLAUDE_JOB_DIR` | env         | enables `# Background Session`                            |
| `CLAUDE_CODE_DISABLE_ATTACHMENTS`             | env         | drops the token-budget section (as does bare mode)        |
| `tengu_verified_vs_assumed`                   | flag        | adds the verified-vs-assumed bullet to `# Doing tasks`    |
| truthy/falsy token sets                       | parsing     | truthy `{1,true,yes,on}`, falsy `{0,false,no,off}`        |

`CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` is a tri-state: truthy disables, explicit falsy enables,
unset falls back to `includeGitInstructions`.

Tripwire (re-run against a new version):

- □ three base-prompt intro variants present; the selector also returns a recorded intro
- □ lean body emits `# Harness`; legacy emits `# System` and `# Doing tasks` separately
- □ path selection checks `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT`, then `lean_prompt` or the legacy model
  list, then `tengu_velvet_tide`, then `simple_system_prompt`
- □ `"lean_body"` and `"repl_working"` each appear once, in the section-list builder
- □ `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` present
- □ `# Language`, `# Output Style: ` and `You have been invoked in the following environment: ` are
  built from attachments, not system-prompt sections
- □ truthy set is `{1,true,yes,on}`, falsy `{0,false,no,off}`

## Tool-description channel

The git instructions ride in the Bash tool `description`, which has a terse (lean) and a legacy
variant selected by the same path gate. Full treatment, including what survives
`CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS`, is in `GIT_USAGE.md`. Verbatim text for the Bash
description, the `# Git` block, and the commit/PR workflow is in `PROMPTS_RENDERED.md`.

## Regenerating the rendered snapshot

`PROMPTS_RENDERED.md` is generated, not hand-written. After preparing a new version:

```
python3 bin/render-prompts.py <version>
```

Anchors live in the `ANCHORS` list at the top of `render-prompts.py`; a `NOT FOUND` report means a
section moved or was reworded and the anchor (and the inventory above) needs updating. Before
treating a missing anchor as a removal, check whether the string is now assembled from parts — see
the grep guidance in the root `CLAUDE.md`.
