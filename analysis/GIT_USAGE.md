# Claude Code Git Usage in System Prompts

Version: 2.1.39

## Key Finding

All git behavioral instructions -- the safety protocol, commit workflow, PR workflow, and attribution -- are carried entirely by the Bash tool's `description` field. There is no git guidance in the main system prompt assembled by `dZ()`.

This means git instructions are invisible if you only examine the system prompt text; they are embedded in the tool definition passed via the `tools` API parameter.

## Where Git Appears in Prompt-Relevant Code

### 1. Bash Tool Description -- `ba4()` / `LmY()` (lines 433856-434004)

The Bash tool description function `ba4()` (line 433856) builds the full tool description and appends the output of `LmY()` (line 433906) at the end. `LmY()` contains three sections:

- "Committing changes with git" -- step-by-step commit workflow with the Git Safety Protocol
- "Creating pull requests" -- step-by-step PR workflow using `gh`
- "Other common operations" -- one-liner for viewing PR comments

Full rendered text: see `PROMPTS_RENDERED_2.1.39.md`, section "Bash Tool Description".
Analysis and source references: see `PROMPTS.md`, section "Prompt Content in Tool Descriptions".

### 2. Git Status Context Injection -- `ZPA()` (line 268192)

At conversation start, the current git status is captured and injected into the first user message as a `<system-reminder>` block. This is informational context only -- it tells the model what branch it's on and what files are changed, but contains no behavioral instructions.

```
gitStatus: This is the git status at the start of the conversation. Note that this status is a snapshot in time, and will not update during the conversation.
Current branch: [BRANCH]

Main branch (you will usually use this for PRs): [MAIN_BRANCH]

Status:
[git status --short output]

Recent commits:
[git log --oneline -n 5]
```

Not included for remote sessions (`CLAUDE_CODE_REMOTE` is set). Truncated at 40k characters.

See `PROMPTS.md`, section "Context Injection" and `PROMPTS_RENDERED_2.1.39.md`, section "Context Injection".

### 3. Plan Mode Agent Restrictions (lines 268605-268606, 268662-268663)

Agents in plan mode are restricted from write operations, including git mutations:

```
- Use Bash ONLY for read-only operations (ls, git status, git log, git diff, find, cat, head, tail)
- NEVER use Bash for: mkdir, touch, rm, cp, mv, git add, git commit, npm install, pip install, or any file creation/modification
```

This appears in plan mode agent definitions, not in the main system prompt.

### 4. Bash Tool Description -- Inline Git Examples (lines 433892-433893)

Two git examples appear in the main body of `ba4()` (before the `LmY()` section), as part of the multi-command guidance:

```
- If the commands are independent and can run in parallel, make multiple Bash tool calls in a single message. For example, if you need to run "git status" and "git diff", send a single message with two Bash tool calls in parallel.
- If the commands depend on each other and must run sequentially, use a single Bash call with '&&' to chain them together (e.g., `git add . && git commit -m "message" && git push`). For instance, if one operation must complete before another starts (like mkdir before cp, Write before Bash for git operations, or git add before git commit), run these operations sequentially instead.
```

These are about command chaining patterns, not git-specific behavior.

## Git Safety Protocol

The full protocol, from `LmY()` at line 433914:

- NEVER update the git config
- NEVER run destructive git commands (push --force, reset --hard, checkout ., restore ., clean -f, branch -D) unless the user explicitly requests
- NEVER skip hooks (--no-verify, --no-gpg-sign, etc) unless the user explicitly requests
- NEVER run force push to main/master, warn the user if they request it
- CRITICAL: Always create NEW commits rather than amending, unless explicitly requested. Pre-commit hook failure means the commit didn't happen, so --amend would modify the wrong commit
- When staging files, prefer specific files by name rather than "git add -A" or "git add ."
- NEVER commit changes unless the user explicitly asks

## Commit Attribution

The commit and PR attribution text is generated by `MZ6()` (line 433718), called from within `LmY()`. The attribution is surface-dependent and configurable.

### Default (CLI and most surfaces)

Commit: `Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>`
PR footer: `[robot emoji] Generated with [Claude Code](https://claude.com/claude-code)`

The model name in the commit trailer is resolved dynamically:
- `qK6()` (line 133933) maps model IDs to display names (e.g., "Opus 4.6", "Sonnet 4.5", "Haiku 4.5")
- `M67()` (line 133970) prefixes with "Claude" to produce e.g. "Claude Opus 4.6"
- If working in an internal Anthropic repo (`XL7()` at line 220321, which checks git remote against a list of Anthropic repos), uses the actual model name
- Otherwise defaults to `"Claude Opus 4.6"` (the `VmA` constant)

### Remote sessions (claude.ai/code)

If `CLAUDE_CODE_REMOTE_SESSION_ID` and `SESSION_INGRESS_URL` are available (and not localhost), both commit and PR attribution use a session URL: `https://[ingress]/code/[session_id]`

If no session URL is available: empty strings (no attribution).

### User configuration overrides

- `config.attribution.commit` -- custom commit trailer string
- `config.attribution.pr` -- custom PR footer string
- `config.includeCoAuthoredBy === false` -- disables all attribution

## Implications

### For reproducing the system prompt

The git instructions are only available if you include a Bash tool with the `LmY()` content in its description. If you're reproducing the Claude Code experience outside of it (e.g., using the Anthropic API directly), you need to either:

1. Embed the git instructions in your Bash tool description (matching how Claude Code does it), or
2. Move them into your system prompt text (which Claude Code does not do)

### For subagents

Subagents spawned via the Task tool do not receive the Bash tool and therefore have no git instructions. The main agent's git instructions explicitly prohibit using TodoWrite or Task tools during commit and PR operations: "NEVER use the TodoWrite or Task tools". This prevents the main agent from delegating git operations to subagents.

### Entanglement

The Bash tool description is a single dynamically-generated string. The git sections (`LmY()`) are concatenated directly to the end of the core Bash usage instructions (`ba4()`). The commit attribution (`MZ6()`) is computed inside `LmY()`, making the description vary based on:

- Current model ID (affects Co-Authored-By name)
- Execution surface (`remote` vs others -- affects attribution format)
- Whether the repo is an internal Anthropic repo (affects model name resolution)
- User config (`attribution`, `includeCoAuthoredBy` settings)

There is no mechanism to include git instructions without the Bash tool, or to include the Bash tool without git instructions.
