# Claude Code System Prompts Analysis

Source: `cli.prettier.js` 2.1.154 (`work/2.1.154/package/cli.prettier.js`)

This document is a behavioral model and landmark index, not a code map. It anchors on stable strings
(section headings, env vars, feature flags) and describes logic declaratively, so it can be
re-corroborated against future versions with the grep recipes below rather than rewritten. Minified
symbol names and line numbers are deliberately omitted — see `GUIDELINES.md`. For the verbatim
rendered text of each section, see `PROMPTS_RENDERED.md`, regenerated by `render-prompts.py`.

## Where the model sees prompt text

Three channels, only the first of which is the API `system` parameter:

1. System prompt text — assembled at runtime from a base prompt plus a set of sections (this doc).
2. Tool descriptions — the `description` field of each tool, which carries substantial instruction
   text. The git workflow lives here, not in the system prompt (see `GIT_USAGE.md`).
3. Context injection — CLAUDE.md and git status, prepended to the first user message as a
   `<system-reminder>` block.

## Assembly model

The system prompt is: base prompt, then the section list, then optional trailing guidance (deferred
tools, MCP CLI). Context injection is delivered separately in the first user message.

### Base prompt

One of these intro strings is chosen by surface:

| Condition                                  | Intro string                                                              |
|--------------------------------------------|---------------------------------------------------------------------------|
| Vertex, or interactive (default)           | `You are Claude Code, Anthropic's official CLI for Claude.`               |
| Non-interactive + append-system-prompt     | `…official CLI for Claude, running within the Claude Agent SDK.`          |
| Non-interactive, no append                 | `You are a Claude agent, built on Anthropic's Claude Agent SDK.`          |

Re-locate: `rg -n "running within the Claude Agent SDK"` — the three intro constants sit together;
the selector keys on a vertex check and a non-interactive/append check.

### Two-path split (keyed on model)

The section list comes in two shapes, selected by the model, not by a standalone feature flag:

- Simple path — a single consolidated core block headed `# Harness`. Used for current models
  (Opus 4.8).
- Legacy path — separate blocks: an intro paragraph, `# System`, `# Doing tasks`, `# Executing
  actions with care`, `# Using your tools`, `# Tone and style`. Used for Sonnet, Haiku, and
  Opus ≤ 4.7.

Override and re-locate: `rg -n "CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT"`. The selector returns simple when
that env var is truthy, legacy when explicit-falsy, else decides by model (Opus 4.8 → simple;
`claude-3-*`, `haiku`, `sonnet`, `opus-4-0/4-1/4-5/4-6/4-7` → legacy), with a client-data /
`tengu_velvet_cascade` override. This is the same model gate that selects the Bash tool description
variant (see `GIT_USAGE.md`).

SDK short-circuit: `rg -n "CLAUDE_CODE_SIMPLE"` (the bare form). When set truthy, the section
builder returns a minimal `CWD:` / `Date:` stub instead of the full prompt.

### Section inventory

Anchor on the heading/phrase in the first column; that is what `render-prompts.py` and any future
grep use. "Path" notes whether a section is simple-only, legacy-only, or both (often with different
wording per path).

| Section (stable anchor)                          | Path        | Gate / condition                                              |
|--------------------------------------------------|-------------|---------------------------------------------------------------|
| `# Harness`                                       | simple      | core block; always on simple path                             |
| intro paragraph (`You are an interactive agent`)  | legacy      | always on legacy path                                         |
| `# System`                                        | legacy      | includes the hooks notice (`Users may configure 'hooks'`)     |
| `# Doing tasks`                                   | legacy      | always; `tengu_verified_vs_assumed` adds one bullet           |
| `# Executing actions with care`                   | both        | always; compact vs full wording                               |
| `# Using your tools`                              | both        | content depends on which tools are present                    |
| `# Tone and style`                                | both        | always                                                        |
| anti-verbosity (`Write code that reads like…`)    | both        | simple: one-liner; legacy: `# Text output (does not apply…)`  |
| action caution (`For actions that are hard to…`)  | simple      | simple path only                                              |
| `# Session-specific guidance`                     | both        | only if any guidance bullet applies (Skill, Agent, schedule)  |
| `# auto memory`                                   | both        | unless dynamic sections excluded; memory content present      |
| `# Environment` (`You have been invoked in…`)     | both        | simple/legacy env block; SDK uses a static variant            |
| `# Language`                                      | both        | only if a non-English locale is configured                    |
| `# Output Style: <name>`                          | both        | only if output style ≠ default (`OUTPUT_STYLES.md`)           |
| `# Background Session`                            | both        | `CLAUDE_CODE_SESSION_KIND=bg` and `CLAUDE_JOB_DIR` set        |
| `# Scratchpad Directory`                          | both        | only if a scratchpad dir is configured                        |
| `# Context management`                            | both        | always                                                        |
| `# Focus mode`                                    | both        | only in focus view mode; wording varies by path               |
| reproduce/verify (`Work step by step:`)           | both        | `CLAUDE_CODE_VERIFY_PROMPT` or `tengu_sparrow_ledger`         |
| investigate-first (`Asking the user a clarifying…`)| both       | only on `claude-opus-4-7` with `CLAUDE_CODE_INVESTIGATE_FIRST`/`tengu_slate_harrier` |
| heron-brook (arbitrary)                            | both        | server/`tengu_heron_brook`-provided string, else absent       |

Re-locate any row: `rg -nF "<anchor>"`. If a grep returns no hit in a new version, the section was
reworded or removed — update the anchor and note the change.

## Gating matrix

Toggles that add, remove, or reshape prompt content. Re-locate each with `rg -n "<name>"`.

| Toggle                                   | Type    | Effect                                                          |
|------------------------------------------|---------|-----------------------------------------------------------------|
| `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT`       | env     | force simple (truthy) / legacy (falsy) path                     |
| `CLAUDE_CODE_SIMPLE`                     | env     | SDK stub prompt (`CWD:`/`Date:` only)                           |
| `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS`   | env     | removes git workflow, `# Git` block, git-status injection       |
| `includeGitInstructions`                 | config  | same as above via config (default on)                           |
| `CLAUDE_CODE_DISABLE_CLAUDE_MDS`         | env     | suppresses the CLAUDE.md context injection                      |
| `CLAUDE_CODE_REMOTE`                     | env     | suppresses git-status injection on remote sessions              |
| `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`   | env     | drops `run_in_background` guidance from tool descriptions       |
| `CLAUDE_CODE_SESSION_KIND` / `CLAUDE_JOB_DIR` | env | enables the `# Background Session` block                        |
| `CLAUDE_CODE_VERIFY_PROMPT`              | env     | enables the reproduce/verify workflow section                   |
| `CLAUDE_CODE_INVESTIGATE_FIRST`          | env     | enables investigate-first (Opus 4.7 only)                       |
| `CLAUDE_CODE_PERFORCE_MODE`              | env     | adds a Perforce note to the injected context                    |
| truthy/falsy token sets                  | parsing | truthy `{1,true,yes,on}`, falsy `{0,false,no,off}` (shared)     |

Tripwire (re-run against a new version):
- □ three base-prompt intro variants present
- □ simple path emits the `# Harness` block; legacy emits `# System` + `# Doing tasks` separately
- □ path selection keys on `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT` then the model
- □ truthy set is `{1,true,yes,on}`, falsy `{0,false,no,off}`

## Tool-description channel

The git instructions ride in the Bash tool `description`, which itself has a terse (simple-model)
and a legacy (older-model) variant selected by the same model gate. Full treatment, including what
survives `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS`, is in `GIT_USAGE.md`. Verbatim text for the Bash
description, the `# Git` block, and the commit/PR workflow is in `PROMPTS_RENDERED.md`.

## Context injection

Prepended to the first user message as a single `<system-reminder>`, wrapping one block per context
key rendered as `# <key>\n<value>`.

- Wrapper anchor: `As you answer the user's questions, you can use the following context:`
- CLAUDE.md block — key `claudeMd`, body opens `Codebase and user instructions are shown below…`.
  Three label variants distinguish project / local / user files. Gated by
  `CLAUDE_CODE_DISABLE_CLAUDE_MDS`.
- Git status block — key `gitStatus`, body opens `This is the git status at the start of the
  conversation…`. Gated by the git switch and `CLAUDE_CODE_REMOTE`; the status output is truncated
  (currently ~2k characters).

Re-locate: `rg -nF "As you answer the user's questions"` for the wrapper; `rg -nF "Codebase and user
instructions are shown below"` and `rg -nF "This is the git status at the start of the conversation"`
for the two blocks.

## Regenerating the rendered snapshot

`PROMPTS_RENDERED.md` is generated, not hand-written. After preparing a new version:

```
python3 bin/render-prompts.py <version>
```

Anchors live in the `ANCHORS` list at the top of `render-prompts.py`; a `NOT FOUND` report means a
section moved or was reworded and the anchor (and the inventory above) needs updating.
